# ADR-029: 문항 평가 — 사전 추론 기반 (예측 난이도 + 내용 검증)

Status: Accepted
Date: 2026-06-19
Deciders: wissens2024, Claude

## Context

채팅·import·수기 작성으로 만들어진 시험 문항의 품질을 평가하려 한다. 고전적 심리측정
지표(문항난이도 P, 변별도 D, IRT)는 **응시자 응답 데이터**가 있어야 산출되지만, 운영 초기엔
응답 데이터가 없다. 논의 결과: 통계 지표도 결국 표본 추정이며, **AI 추론으로 같은 평가를
사전(a priori)에 수행**하는 것이 가능하고 본 플랫폼의 성격(LLM 추론 기반)과도 맞다. 사람
응시를 기다려야 한다는 것은 제약이 아니라 선택지 중 하나일 뿐이다. 현재 `AssessmentValidator`
(정답·해설·보기·난이도라벨 정합 LLM 검수)는 있으나, 독립적 "예상 난이도"와 통합 평가 노출은
없다.

## Decision

문항 평가를 **사전 추론(LLM)** 으로 수행한다. **1단계(본 ADR 구현 범위)**: (a) 내용 검증
(기존 AssessmentValidator + 생성 가드 — 정답 유일성·보기 중복·언어·그림의존), (b) **예상 난이도
상/중/하** 를 LLM이 문항 자체 기준으로 독립 추정해 문항에 부착하고 UI 해설에 "예상 난이도: 상"
으로 노출한다. 예측치임을 명시한다(절대원칙 5 — 추정을 사실처럼 내보내지 않음).

## Considered Alternatives

1. **사후 통계만 인정(응시 데이터 필수)** — 변별도/난이도는 사람이 풀어야만 산출. — **기각**:
   운영 초기 데이터 0, 평가를 아예 못 함. 통계도 표본 추정이라 AI 사전 추론과 본질이 다르지 않다.
2. **모의 응시자 시뮬레이션을 1단계에 포함** — 능력군별 가상 응시자로 예측 P̂·변별도 D̂ 산출. —
   **연기(기각 아님)**: 가치 크나 비용·복잡도 큼. 1단계는 예측 난이도+검증으로 빠르게 내고,
   시뮬레이션 변별도는 **2단계(후속 ADR)** 로 분리한다.
3. **요청 난이도(target)를 그대로 표시** — 생성 시 지정한 난이도를 예상치로 노출. — **기각**:
   그건 입력값(에코)이지 평가가 아니다. 독립 추정이어야 의미가 있다.

## Consequences

- Positive: 응시 데이터 0으로도 즉시 문항 평가(예상 난이도) 제공. AI 생성·import·수기 작성 공통
  적용. 2단계(모의 응시자 변별도)로 자연 확장.
- Negative: 예상 난이도는 LLM 추정이라 절대 정확도 한계(상대 비교·이상치 플래그에 더 유효).
  요청 난이도를 에코할 위험 → 프롬프트로 "문항 자체 기준 독립 평가" 강제.
- Follow-up: 2단계 모의 응시자 기반 예측 변별도·오답지 매력도(별도 ADR). 실제 응시 데이터가
  쌓이면 예측치 calibration.

## Assumptions

- LLM이 객관식 문항의 체감 난이도를 상/중/하로 유의미하게 구분할 수 있다(완벽하진 않아도 순위
  신호로 유효).
- 1단계 예측 난이도는 ephemeral 채팅 문항·문제은행 문항 모두에 부착 가능하다.
